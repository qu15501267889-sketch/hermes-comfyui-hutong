# 常见工作流配方（概念级蓝图）

配方只给**结构与检查点**，不给固定类名/模型名/slot index —— 节点与模型必须从目标实例的
`object_info` / `hb_list_models` 实取。

## 统一模板（每个配方都按这 7 问写）

1. 用户意图 + 典型触发句
2. 需要从用户 / 当前画布获得的必要输入
3. 逻辑阶段顺序（输入 → 核心处理 → 可选控制/后处理 → 输出）
4. 最小版本 + 可选增强分支
5. 需要检查的运行时节点能力与模型类别
6. 常见结构错误 + 落图后核验项
7. 哪些信息缺失必须问、哪些可用默认值

## 1. 文本生成图像

- **阶段**：提示词输入 → 模型装载（主模型 + 文本编码器 + VAE）→ 正负条件 → 空 latent → 采样 → 解码 → 保存/预览
- **必要数据流**：`CONDITIONING` 正负各一路进采样器；`LATENT` 从空 latent 进 `latent_image`
- **模型体系决定拓扑** —— SD/SDXL/Flux/Qwen 等不要混成一种模板；负向条件在 cfg=1 类配方里**不生效**
- **需确认**：尺寸/比例、步数档、是否要负向词
- **核验**：采样器 `positive`/`negative`/`latent_image` 三个必需输入都有 link（漏连 = 段被静默剪掉，
  status 仍 success）

## 2. 图像到图像

- **阶段**：载图/预处理 → 编码（`VAEEncode`）或模型自带 image 输入 → 条件 → 采样（低 denoise）→ 解码 → 输出
- **关键分叉先问清**：「保留构图做变化」与「参考图生成新图」结构不同（前者 denoise 低、后者接近新生成）
- **尺寸**：目标宽高通常需与被编码图一致；换比例要连同预处理缩放一起改
- **核验**：denoise / 步数 实际写进 widget 的值（回读存档核对，别只信 update 返回 ok）

## 3. 局部重绘 / 蒙版

- **阶段**：目标图 → mask 来源（手绘 / 检测器 / 分割模型）→ mask 与图尺寸对齐 → 编码（inpaint 系）→ 采样 → 解码 → 合成 → 输出
- **语义必先确认**：白区是「要改的」还是「要保留的」；mask 与图的尺寸关系
- **⚠️ `VAEEncodeForInpaint` 只配局部 mask**：它会把 mask 区域先抹成中灰再编码；
  **全图 mask（全1）喂它 = 整张图变常数灰**（RGB≈127、std≈0.3），denoise 0.35 也救不回来
- **全局调整（光影重绘 / 风格化 / 全图 img2img）用普通 `VAEEncode`**
- **瘦身类 img2img 实测参数**：denoise **0.55 会把男人画娘化**，**0.2~0.3 性别/特征稳定**；
  提示词**必须性别中性**（输入男女不定），负向加 `changed gender, feminine curves, muscular male` 防串性；
  别用整人 mask 重绘（mask 外会清脏）
- **核验**：解出后先用 PIL 读 `stddev`，`max(stddev) < 8` = 常数灰（数据结构/抹灰问题），别只看 `status: success`

## 4. 放大 / 超分

- **两种档次分开看**：① 无损放大模型（ESRGAN 类）② 生成式精修放大（分块重采样）
- **放大倍数在模型文件本身**，不在节点 widget 里 —— 读 loader 的模型名按 `x4`/`x2` 后缀算
- **⚠️ 「降分辨率反而更慢」成因**：720P 只降采样面积 ~44%，但链尾挂着 4× 超分 → 输出 ~5120×2560，
  放大面积比 1080P 采样还大。真正提速 = **旁路/关闭尾部超分**（`mode:4`），不是降主采样
- **画质与分块是两件事**：分块只解决显存，**不改画质**。通用老超分模型（如 RealESRGAN_x4plus）
  人像必出油画感 —— 换人像向超分模型才是画质解
- **尺寸爆的正解**：4× 后接「限长边缩放」节点（如限回 2560）—— 细节吃满、尺寸可控
- **生成式精修管线**：分块重采样 Provider（provider 出 `UPSCALER`，**不是直接连图**，只能喂
  Iterative 放大节点）→ 迭代放大（2x / steps=2 / 带 vae）→ 输出；配放大专用提示词
  （"高清细节 / 真实皮肤纹理 / 锐利无涂抹"）
- **核验**：产出文件实际像素尺寸 + 用 `vision_analyze` 亲眼看画质（数字指标不够）

## 5. 条件 / 参考控制（ControlNet、参考图、锁脸）

- **阶段**：参考图/条件图 → 预处理（预处理器节点）→ 条件注入（控制网络/参考槽）→ 与主链在采样前合流
- **约束**：别默认加；用户没要求就不追加。加了要说明它锁什么（构图/姿势/脸/风格）
- **核验**：条件节点的输出确实进到目标采样节点的对应输入槽；强度/结束步不该写死为默认却没说

## 6. 视频生成

- **先确认影响拓扑与资源负担的项**：目标模态、时长/帧率、模型家族；用户没说才问
- **阶段**：条件（文本/首帧图）→ 视频模型装载 → 采样（批量帧）→ 解码 → 帧率/编码 → 保存
- **显存与帧数强相关**：帧数/分辨率先给保守档，跑通再加
- **核验**：产出是视频容器而非单帧；帧数/尺寸与设定一致

## 7. 视频后处理

- **阶段**：读视频 → 拆帧 → 逐帧处理（放大/插帧/去噪/风格）→ 合帧 → 写回视频
- **核验**：帧数守恒；音轨是否保留（应主动确认）

## 8. 多段串联修图链（本项目主线）

- **单段多任务 = 过载**：把 4 件事塞进一段 25 步，注意被摊薄 —— 实测「瘦身没效果、美白磨皮变差」
- **按任务性质分组，每段 ≤2 件同类事**，大结构改动（身材）**独享一段**，段间在资源允许时串联
- **段词结构**：保真总括（身份/五官/服装不变）+ 各功能句分号隔开 + 融合收尾句（**只放最后一段**）
- **段间连法**：上段「解码输出」→ 下段「TE 的 image_1」；每段独立预览 + 独立 randomize 种子
- **⚠️ 串联噪声 = 多级劣化**：挨个排查前先算**相邻像素差分**（PIL 灰度 256²、邻差均值；正常 4~6）
  按 mtime 排开看趋势 —— **随时序单调递增 = 链式累积**（回查 latent 源与旁路），
  **恒定高值 = 单点故障**（查那一个节点）
- **排查期铁律：用随机种子**（固定种子会让坏结果确定性复现，把偶发误判成必现）
